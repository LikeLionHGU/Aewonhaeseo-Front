# 백엔드 요청 — 기업 담당자가 직접 API 키를 발급받는 경로

**요청일** 2026-08-21 · **확인 환경** `https://1-201-116-24.sslip.io`

> **완료 (2026-08-21)** — 요청한 세 경로가 이름까지 그대로 올라왔습니다. 담당자 계정으로
> 발급 → `/open-api/v1/me` 호출 → 폐기까지 확인했고, 아래에서 강조한 **소유권 검사도
> 걸려 있습니다**(남의 기업 이름으로 발급·남의 키 폐기 모두 `403
> OPEN_API_ORGANIZATION_FORBIDDEN`). 이 문서는 무엇을 왜 요청했는지 남기기 위해 둡니다.
>
> 한 가지만 스펙에 반영해 주시면 좋겠습니다 — 담당자 발급은 `requests_per_minute`가
> **60을 넘으면 400**(`must be less than or equal to 60`)인데 스펙에 상한이 적혀 있지 않아
> 실제로 호출해 보고서야 알았습니다. `IssueRequest.requests_per_minute`에 `maximum: 60`을
> 넣어 주시면 다음 사람이 헤매지 않습니다. (관리자 경로는 120도 받습니다.)

## 먼저, 지금 만들어 주신 것은 잘 됩니다

프론트에서 붙여 전 과정을 확인했습니다.

```
POST /api/v1/admin/open-api/organizations/1/keys   → 201, api_key = awon_live_…
GET  /open-api/v1/me            (X-API-Key)        → 200 {organization_name, key_name, requests_per_minute}
POST /open-api/v1/mappings/columns (X-API-Key)     → 200
       T-N        → WQ-005 exact
       측정일자     → MD-006 exact
       우리회사SS   → WQ-004 exact  output_column=WQ-004@우리회사   ← composite 매칭까지 동작
       알수없는칸   → unmapped
DELETE /api/v1/admin/open-api/organizations/1/keys/3 → 204
       폐기 후 같은 키로 호출     → 401 OPEN_API_KEY_INVALID
```

발급 응답의 `warning`("이 키는 다시 조회할 수 없습니다…")도 화면에 그대로 띄우고 있습니다.

## 요청: 담당자 본인이 발급받는 경로

지금은 발급·조회가 **관리자 전용**(`/api/v1/admin/open-api/...`)입니다. 일반 계정으로 부르면
`403 ACCESS_DENIED`입니다. 그래서 기업 담당자가 소개 페이지에서 신청해도 스스로 키를 받을 수
없고, 관리자에게 부탁해 대신 발급받아야 합니다. 담당자 입장에서 흐름이 끊깁니다.

아래 세 경로를 **로그인 쿠키(AWON_ACCESS_TOKEN) 인증, 일반 사용자 허용**으로 열어 주시면
프론트는 고칠 것 없이 바로 동작합니다. 이미 이 경로를 전제로 붙여 두었고, 없으면 404를 잡아
"서버에 경로가 없습니다"라고 표시하고 있습니다.

### 1) `POST /api/v1/open-api/keys` — 내 키 발급

```json
// 요청
{ "organization_name": "어원환경", "key_name": "운영 서버", "requests_per_minute": 60 }
```

- 응답은 기존 `IssuedResponse`를 그대로 재사용해 주세요 (`organization` · `key` · `api_key` · `warning`).
- `requests_per_minute`는 선택 — 없으면 서버 기본값.
- 첫 발급이면 기업을 만들고 **호출한 계정에 묶어** 주세요. 이후 발급은 그 기업에 키만 더합니다.

**중요 — 소유권 검사가 필요합니다.** 이 검사가 없으면 아무 계정이나
`organization_name: "어원 Open API"`로 보내 남의 기업 키를 발급받고, 그 기업의 전용 사전을
읽고 쓸 수 있습니다. 계정이 이미 다른 기업에 묶여 있거나 남의 기업 이름을 보내면 `403`으로
막아 주세요.

계정당 활성 키 개수 상한(예: 5개)도 있으면 좋겠습니다.

### 2) `GET /api/v1/open-api/keys` — 내 키 목록

- 응답은 기존 `KeyResponse[]` 그대로. 원문 없이 `prefix`만.
- 호출한 계정에 묶인 기업의 키만 돌려주세요.

### 3) `DELETE /api/v1/open-api/keys/{keyId}` — 내 키 폐기

- `204`. 자기 기업 키가 아니면 `403`.

## 참고: 프론트가 쓰는 값

- 발급 화면이 보내는 것은 위 세 필드뿐입니다. 담당자 이름·이메일·연락처·사용 목적은 저장할
  자리가 없어서 **입력칸을 두지 않았습니다.** 신청 이력으로 남겨야 한다면 필드를 알려 주시면
  화면에 되살립니다.
- 키 원문은 발급 직후 화면에서 한 번만 보여주고 어디에도 저장하지 않습니다. 목록은 `prefix`만
  씁니다.
- 브라우저에서 API 키로 `/open-api/v1/*`을 부르지 않습니다. 키를 프런트엔드 코드에 두지 말라는
  안내와 어긋나기 때문에, 화면에서는 확인용 `curl` 명령만 내줍니다.
